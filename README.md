# TechShop — интернет-магазин

Проект № 5 из Java_Projects.docx. Приложение на Java Spring Boot и MySQL с интерфейсом на HTML, CSS и JavaScript.

## Запуск на этом Mac

Дважды нажмите на `start.command` в папке проекта. Можно запустить из терминала:

```sh
cd /Users/diasss/programming_project/project
./run-local.sh
```

После сообщения о запуске откройте http://localhost:8080.

Скрипт создаёт отдельную локальную MySQL-базу в `.local/mysql`, собирает приложение и запускает магазин. На этом компьютере Java 21, Maven и скачанные зависимости уже подготовлены в `.local`. MySQL установлен отдельно. По умолчанию используется порт базы 33308, порт приложения — 8080. Данные сохраняются после остановки. Для завершения нажмите Ctrl+C в окне терминала.

Если порт занят, укажите другой:

```sh
LOCAL_DB_PORT=33309 PORT=8081 ./run-local.sh
```

Локальная база этого скрипта использует root без пароля и слушает только 127.0.0.1. Это режим для учебной демонстрации на своём компьютере. Скрипт не меняет существующие базы и не запускается как системный сервис.

## Демонстрационные аккаунты

| Роль | Email | Пароль |
| --- | --- | --- |
| Покупатель | customer@techshop.local | DemoUser123! |
| Администратор | admin@techshop.local | DemoAdmin123! |

Аккаунты добавляются только при включённом профиле `demo`. Пароли хранятся в базе в виде BCrypt-хешей. При обычной регистрации пользователь получает роль Customer.

Профиль demo создаёт три категории и девять реальных моделей Logitech, VXE, VGN и HyperX с локальными фотографиями. Цены и остатки заданы для демонстрации. Старые условные модели обновляются с сохранением id и текущего остатка. Повторный запуск сохраняет существующие реальные модели, их цены, остатки, аккаунты и заказы.

## Что работает

- Регистрация, вход, выход и роли Customer и Admin.
- Каталог с описаниями, ценами, категориями и остатками из MySQL.
- Поиск по названию, фильтры по категории и цене, сортировка.
- Личная корзина: добавление, изменение количества и удаление позиции.
- Плавающая кнопка справа снизу открывает небольшое окно выбранных товаров с суммой и оформлением.
- Отдельное окно оплаты с номером тестовой карты, сроком действия и CVC, проверкой полей и подтверждением платежа.
- Оформление заказа с расчётом суммы на сервере.
- Проверка остатков и защита от одновременной покупки последней единицы товара.
- История покупок, симуляция оплаты и отмена с возвратом товара на склад.
- Панель администратора: CRUD товаров и категорий, управление заказами, статистика продаж и Chart.js.
- Адаптивный интерфейс и понятные сообщения об ошибках.

Покупатель видит свои корзину и заказы. Администратор управляет каталогом и статусами заказов. В запросах, меняющих данные, используется CSRF-токен. Сессия хранится в HttpOnly-cookie.

## Как проверить вручную

1. Откройте магазин. Найдите товар через поиск или фильтры.
2. Войдите как покупатель, добавьте товар в корзину и измените количество.
3. Оформите заказ. Откроется окно оплаты: нажмите «Заполнить тестовой картой», затем «Оплатить». Деньги не списываются. У неоплаченного заказа окно можно открыть повторно кнопкой «Оплатить» в разделе «Мои заказы».
4. Выйдите и войдите как администратор. Откройте «Управление» → «Заказы».
5. Подтвердите заказ, отправьте и завершите его. Сумма появится в статистике.
6. В разделах «Товары» и «Категории» проверьте создание и изменение записей.

Товар из корзины или заказа удалить нельзя. Категорию с товарами также удалить нельзя. Заказы и их позиции не редактируются через обычный CRUD.

Статусы заказа: NEW → CONFIRMED → SHIPPED → COMPLETED. До отправки можно отменить заказ. Отправка доступна после оплаты. Повторная отмена не увеличивает остаток повторно. Оплата — симуляция статусов UNPAID, PAID и REFUNDED. Форма принимает тестовую карту 4242 4242 4242 4242. Номер карты, срок, CVC и имя проверяются в браузере, не отправляются на сервер и не сохраняются. Кнопка «Заполнить тестовой картой» автоматически подставляет подходящие данные.

## Запуск на другом компьютере

Нужны Java 17 или 21, Maven и MySQL 8.0.16 или новее. На другом компьютере локальные инструменты нужно установить отдельно. macOS/Linux могут использовать `run-local.sh`, если команды `java`, `mvn`, `mysqld`, `mysql` и `mysqladmin` доступны в терминале.

Для работы с уже установленным сервером MySQL создайте базу:

```sh
mysql -u root -p < sql/create-database.sql
```

macOS / Linux:

```sh
export DB_URL='jdbc:mysql://localhost:3306/ecommerce?connectionTimeZone=UTC'
export DB_USERNAME=root
export DB_PASSWORD='ваш_пароль_MySQL'
mvn -DskipTests package
java -jar target/shop-0.0.1-SNAPSHOT.jar --spring.profiles.active=demo
```

Windows PowerShell:

```powershell
$env:DB_URL = "jdbc:mysql://localhost:3306/ecommerce?connectionTimeZone=UTC"
$env:DB_USERNAME = "root"
$env:DB_PASSWORD = "ваш_пароль_MySQL"
mvn -DskipTests package
java -jar target/shop-0.0.1-SNAPSHOT.jar --spring.profiles.active=demo
```

В PowerShell базу можно создать в MySQL Workbench или через команду `mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS ecommerce CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"`.

Профиль demo применяет `src/main/resources/schema.sql` при запуске. Схема не удаляет данные. Hibernate проверяет таблицы через `ddl-auto=validate`. Если уже загружен прежний `seed.sql`, demo-профиль заменит старые демонстрационные названия и добавит недостающие модели. Текущие остатки и ранее оформленные заказы сохраняются.

Для запуска без демонстрационных аккаунтов примените `schema.sql` вручную и не передавайте `--spring.profiles.active=demo`.

## Тесты

На этом Mac дважды нажмите на `test.command`. Скрипт сам выберет Java и Maven, подключит MySQL или запустит его и создаст отдельную тестовую базу. Предварительно запускать магазин не требуется.

Из терминала в папке проекта:

```sh
./test.command
```

Для одного набора тестов: `./test.command CatalogTest`. Для отдельной проверки: `./test.command 'ShopFlowTest#concurrentOrdersCannotOversellLastProduct'`.

При успехе в конце появятся `BUILD SUCCESS` и «Все тесты прошли». Подробные результаты находятся в `target/surefire-reports`.

Тесты используют отдельную базу MySQL. ShopFlowTest очищает все шесть таблиц этой базы до и после каждого сценария. Не указывайте адрес базы магазина в TEST_DB_URL.

```sh
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS ecommerce_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
export TEST_DB_URL='jdbc:mysql://localhost:3306/ecommerce_test?connectionTimeZone=UTC'
export TEST_DB_USERNAME=root
export TEST_DB_PASSWORD='ваш_пароль_MySQL'
mvn test
```

В PowerShell переменные устанавливаются через `$env:TEST_DB_URL`, `$env:TEST_DB_USERNAME` и `$env:TEST_DB_PASSWORD`.

Проверено 29 автоматизированных тестов: CRUD, регистрация, хеширование паролей, роли, CSRF, личная корзина, оформление, отмена, статусы и защита от одновременной продажи. В Chrome проверен путь от каталога до завершённого заказа, работа статистики и экран шириной 390 px. Для нового интерфейса отдельно проверены мини-корзина, валидация оплаты, отсутствие передачи карточных данных, локальные фотографии и сохранность заказов при обновлении каталога.
