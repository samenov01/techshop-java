# API магазина

Базовый адрес: http://localhost:8080. POST и PUT принимают JSON, кроме входа: он использует application/x-www-form-urlencoded. Ответы — JSON. DELETE возвращает 204 для удаления товара или категории; удаление позиции корзины возвращает обновлённую корзину с кодом 200.

## Вход и сессия

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | /api/auth/csrf | Получить CSRF-токен, доступен без входа |
| POST | /api/auth/register | Регистрация покупателя, 201 |
| POST | /api/auth/login | Вход по email и password, 200 |
| POST | /api/auth/logout | Выход, 204 |
| GET | /api/auth/me | Текущий пользователь |

Перед POST, PUT и DELETE получите `/api/auth/csrf` и передайте полученный token в заголовке с именем headerName. Сохраняйте cookie сессии. После входа и выхода получите токен заново.

Регистрация:

```json
{
  "name": "Покупатель",
  "email": "student@example.com",
  "password": "ExamplePass123!"
}
```

Роль при регистрации всегда CUSTOMER. Пароль — от 8 до 60 символов и до 72 байт UTF-8. Хеши паролей не возвращаются в API.

## Категории

| Метод | Адрес | Доступ |
| --- | --- | --- |
| GET | /api/categories | Всем |
| GET | /api/categories/{id} | Всем |
| POST | /api/categories | Admin |
| PUT | /api/categories/{id} | Admin |
| DELETE | /api/categories/{id} | Admin |

Тело создания и изменения: `{"name":"Мониторы"}`. Название обязательно, до 100 символов, уникально. Удаление категории с товарами возвращает 409.

## Товары

| Метод | Адрес | Доступ |
| --- | --- | --- |
| GET | /api/products | Всем |
| GET | /api/products/{id} | Всем |
| POST | /api/products | Admin |
| PUT | /api/products/{id} | Admin |
| DELETE | /api/products/{id} | Admin |

Параметры списка: search, categoryId, minPrice, maxPrice, sort. Сортировка: newest, priceAsc, priceDesc, nameAsc, nameDesc.

Пример: `/api/products?search=мышь&minPrice=1000&maxPrice=10000&sort=priceAsc`.

Тело создания и изменения:

```json
{
  "name": "Мышь M2",
  "description": "Проводная мышь",
  "price": 6500.00,
  "stock": 10,
  "categoryId": 1
}
```

categoryId должен существовать. Название — до 150 символов, описание — до 5000. Цена больше нуля, до 10 цифр перед десятичной точкой и до двух после неё. Остаток — целое число от 0 до 2147483647. DELETE возвращает 204: товар скрывается из каталога и панели управления, а его позиции удаляются из всех корзин. История покупок сохраняет название, количество и цену. Удалённый товар недоступен по GET и PUT и не может быть добавлен в корзину.

## Корзина

Все операции используют корзину текущего пользователя.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | /api/cart | Состав, сумма и количество |
| POST | /api/cart | Добавить товар |
| PUT | /api/cart/{productId} | Установить количество |
| DELETE | /api/cart/{productId} | Удалить позицию |

Добавление: `{"productId":1,"quantity":1}`. Изменение: `{"quantity":2}`. Количество — целое число от 1 до 10000, не больше доступного остатка. Корзина не резервирует товары.

## Заказы покупателя

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | /api/orders | История своих покупок |
| POST | /api/orders | Оформить текущую корзину, 201 |
| POST | /api/orders/{id}/pay | Подтвердить симуляцию оплаты |
| POST | /api/orders/{id}/cancel | Отменить заказ до отправки |

Тело этих запросов не требуется. Номер карты, срок и CVC из окна оплаты не отправляются в API; форма использует только тестовые данные. Цена, сумма, покупатель и состав берутся на сервере. Проверка остатков, создание заказа, списание товаров и очистка корзины выполняются одной транзакцией. Заказ другого пользователя нельзя оплатить или отменить.

## Панель администратора

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | /api/admin/orders | Все заказы |
| PUT | /api/admin/orders/{id}/status | Изменить статус |
| GET | /api/admin/statistics | Число заказов и товаров, сумма продаж и данные диаграммы |

Тело смены статуса: `{"status":"CONFIRMED"}`.

Переходы: NEW → CONFIRMED → SHIPPED → COMPLETED. NEW и CONFIRMED можно отменить через CANCELLED. Отправка требует статуса оплаты PAID. При отмене остатки возвращаются один раз, PAID меняется на REFUNDED.

Статистика учитывает в сумме продаж только оплаченные завершённые заказы. Данные диаграммы группируются по дате оформления за последние 14 дней.

## Ошибки

- 400 — неверные данные, формат запроса или недопустимый диапазон цен.
- 401 — требуется вход или пароль неверен.
- 403 — недостаточно прав или отсутствует корректный CSRF-токен.
- 404 — запись не найдена или чужой заказ.
- 409 — конфликт данных, нехватка товара или недопустимый переход статуса.

```json
{
  "message": "Проверьте введённые данные",
  "errors": {
    "stock": "Остаток не может быть отрицательным"
  }
}
```

Коллекция Postman содержит запросы авторизации, каталога, корзины, заказов и управления. Для административных операций сначала войдите как Admin. После входа заново выполните запрос получения CSRF-токена.
