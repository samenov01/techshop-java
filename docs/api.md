# API третьей недели

Базовый адрес: http://localhost:8080. Тело запросов POST и PUT передаётся в формате JSON с заголовком `Content-Type: application/json`.

## Категории

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | /api/categories | Список категорий, 200 |
| GET | /api/categories/{id} | Категория по id, 200 |
| POST | /api/categories | Создать категорию, 201 и заголовок Location |
| PUT | /api/categories/{id} | Изменить название, 200 |
| DELETE | /api/categories/{id} | Удалить пустую категорию, 204 |

Тело POST и PUT:

```json
{
  "name": "Мониторы"
}
```

Название обязательно, до 100 символов. Две категории с одинаковым названием создать нельзя. Пробелы по краям удаляются.

## Товары

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | /api/products | Список товаров, 200 |
| GET | /api/products/{id} | Товар по id, 200 |
| POST | /api/products | Создать товар, 201 и заголовок Location |
| PUT | /api/products/{id} | Изменить товар, 200 |
| DELETE | /api/products/{id} | Удалить товар без ссылок из корзины и заказов, 204 |

Тело POST и PUT:

```json
{
  "name": "Мышь M2",
  "description": "Проводная мышь",
  "price": 6500.00,
  "stock": 10,
  "categoryId": 1
}
```

Замените categoryId на id существующей категории. В PUT нужно передать все пять полей. Название — до 150 символов, описание — до 5000. Цена больше нуля, до 10 цифр перед десятичной точкой и до двух после неё. Остаток — целое неотрицательное число.

Пример ответа на создание товара в новой базе:

```json
{
  "id": 4,
  "name": "Мышь M2",
  "description": "Проводная мышь",
  "price": 6500.00,
  "stock": 10,
  "categoryId": 1,
  "categoryName": "Мыши"
}
```

id назначается базой данных, поэтому его фактическое значение может отличаться.

## Ошибки

- 400 — пустые поля, неверный JSON, отрицательный остаток, дробное количество или неверная цена.
- 404 — товар или категория не найдены, в том числе категория из тела запроса.
- 409 — название категории занято либо запись нельзя удалить из-за связей.

```json
{
  "message": "Проверьте введённые данные",
  "errors": {
    "stock": "Остаток не может быть отрицательным"
  }
}
```

## Проверка через Postman

Импортируйте `shop.postman_collection.json`. Адрес хранится в переменной baseUrl. Запустите запросы создания категории и товара: коллекция сохранит полученные id в categoryId и productId. После этого можно получить и изменить записи, проверить запрет удаления занятой категории, затем удалить товар и категорию.

Это локальное API третьей недели. Регистрация, проверка ролей, операции с корзиной и оформление заказа пока не имеют endpoint-ов.
