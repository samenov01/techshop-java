# Проект базы данных

Это схема для дальнейшей реализации, таблицы в MySQL пока не созданы. Все id — BIGINT с автоматическим увеличением. Поля обязательны, если отдельно не указано другое. PK — первичный ключ, FK — внешний ключ.

## users — пользователи

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер пользователя |
| name | VARCHAR(100) | Имя |
| email | VARCHAR(255), UNIQUE | Email для входа |
| password_hash | VARCHAR(255) | Хеш пароля |
| role | VARCHAR(20) | CUSTOMER или ADMIN |

## categories — категории

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер категории |
| name | VARCHAR(100), UNIQUE | Название |

## products — товары

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер товара |
| category_id | BIGINT, FK → categories.id | Категория |
| name | VARCHAR(150) | Название |
| description | TEXT | Описание |
| price | DECIMAL(12, 2) | Цена в тенге, больше нуля |
| stock | INT | Остаток, не меньше нуля |
| active | BOOLEAN | Показывать ли товар в каталоге |

## cart_items — позиции корзины

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер позиции |
| user_id | BIGINT, FK → users.id | Покупатель |
| product_id | BIGINT, FK → products.id | Товар |
| quantity | INT | Количество, больше нуля |

Пара (user_id, product_id) уникальна. Отдельная таблица carts пока не нужна: у каждого пользователя одна текущая корзина. Цена в корзине берётся из products. Неактивный товар оформить нельзя.

## orders — заказы

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер заказа |
| user_id | BIGINT, FK → users.id | Покупатель |
| created_at | DATETIME | Дата оформления |
| status | VARCHAR(20) | NEW, CONFIRMED, SHIPPED, COMPLETED, CANCELLED |
| payment_status | VARCHAR(20) | UNPAID, PAID, REFUNDED |
| total_amount | DECIMAL(12, 2) | Сумма заказа |
| recipient_name | VARCHAR(100) | Имя получателя |
| phone | VARCHAR(30) | Телефон получателя |
| delivery_address | VARCHAR(255) | Адрес доставки |

## order_items — позиции заказа

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер позиции |
| order_id | BIGINT, FK → orders.id | Заказ |
| product_id | BIGINT, FK → products.id | Товар |
| product_name | VARCHAR(150) | Название на момент покупки |
| quantity | INT | Количество, больше нуля |
| unit_price | DECIMAL(12, 2) | Цена на момент покупки |

Пара (order_id, product_id) уникальна. Название и цена сохраняются отдельно, чтобы изменение товара не меняло старый заказ. Общая сумма считается по этим позициям на сервере.

## Связи и ограничения

- Один пользователь имеет от нуля до многих позиций корзины и заказов.
- Одна категория содержит от нуля до многих товаров. Каждый товар относится к одной категории.
- Один товар может встречаться во многих корзинах и заказах.
- У оформленного заказа минимум одна позиция. Это проверяется в Service при создании заказа.
- Все внешние ключи обязательны. На FK нужны индексы, на цену и количества — ограничения CHECK.
- Существующие заказы и их позиции не удаляются через обычный CRUD. Удаление связанных пользователей и товаров не должно каскадно стирать историю.
- Физически удалить товар можно только при отсутствии ссылок на него; иначе он скрывается через active. Скрытый товар может оставаться в корзине, но оформить его нельзя.
- Допустимые значения ролей и статусов будут ограничены в базе и Java. Переходы статусов проверяются в Service.
