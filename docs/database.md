# Проект базы данных

Схема реализована в src/main/resources/schema.sql. Hibernate проверяет соответствие таблиц сущностям при запуске. Все id — BIGINT с автоматическим увеличением. Поля обязательны, если отдельно не указано другое. PK — первичный ключ, FK — внешний ключ.

## users — пользователи

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер пользователя |
| name | VARCHAR(100) | Имя |
| email | VARCHAR(255), UNIQUE | Email для входа |
| password_hash | VARCHAR(255) | Хеш пароля |
| role | VARCHAR(20) | CUSTOMER или ADMIN |

## categories — категории

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер категории |
| name | VARCHAR(100), UNIQUE | Название |

## products — товары

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер товара |
| category_id | BIGINT, FK → categories.id | Категория |
| name | VARCHAR(150) | Название |
| description | TEXT | Описание |
| price | DECIMAL(12, 2) | Цена в тенге, больше нуля |
| stock | INT | Остаток, не меньше нуля |
| active | BOOLEAN | true — в каталоге, false — удалён |

## cart_items — позиции корзины

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер позиции |
| user_id | BIGINT, FK → users.id | Покупатель |
| product_id | BIGINT, FK → products.id | Товар |
| quantity | INT | Количество, больше нуля |

Пара (user_id, product_id) уникальна. У пользователя одна текущая корзина, поэтому отдельная таблица carts не нужна. Цена берётся из products.

## orders — заказы

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер заказа |
| user_id | BIGINT, FK → users.id | Покупатель |
| created_at | DATETIME | Дата оформления |
| status | VARCHAR(20) | NEW, CONFIRMED, SHIPPED, COMPLETED, CANCELLED |
| payment_status | VARCHAR(20) | UNPAID, PAID, REFUNDED |
| total_amount | DECIMAL(12, 2) | Сумма заказа |

## order_items — позиции заказа

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | BIGINT, PK | Номер позиции |
| order_id | BIGINT, FK → orders.id | Заказ |
| product_id | BIGINT, FK → products.id | Товар |
| product_name | VARCHAR(150) | Название на момент покупки |
| quantity | INT | Количество, больше нуля |
| unit_price | DECIMAL(12, 2) | Цена на момент покупки |

Пара (order_id, product_id) уникальна. Название и цена сохраняются отдельно, чтобы изменение товара не меняло старый заказ. Общая сумма рассчитывается на сервере по сохранённым ценам позиций при оформлении заказа.

## Связи и ограничения

- Один пользователь имеет от нуля до многих позиций корзины и заказов.
- Одна категория содержит от нуля до многих товаров. Каждый товар относится к одной категории.
- Один товар может встречаться во многих корзинах и заказах.
- У оформленного заказа минимум одна позиция. Пустую корзину сервис не оформляет.
- Все внешние ключи обязательны. MySQL создаёт индексы для внешних ключей. Цена и количества проверяются ограничениями CHECK.
- Существующие заказы и их позиции не удаляются через обычный CRUD. Удаление связанных пользователей и товаров не должно каскадно стирать историю.

Схема связей: [PNG](../design/database.png), [Mermaid](../design/database.mmd).

CRUD реализован для categories и products. Пользователи создаются через регистрацию, корзина изменяется отдельными операциями, заказы оформляются из корзины. Заказы и их позиции не редактируются и не удаляются через обычный CRUD. Удаление товара устанавливает active=false и удаляет его позиции из всех корзин. Строка товара сохраняется для связей с историей заказов. В каталоге, панели управления и статистике количества учитываются только active=true. Роли и статусы ограничены CHECK-условиями в MySQL, допустимые переходы проверяются в Service.

Оформление заказа выполняется в одной транзакции: блокируется строка покупателя, затем строки товаров по возрастанию id. После проверки наличия сохраняются заказ и позиции, уменьшаются остатки и очищается корзина. Отмена блокирует заказ и возвращает остатки один раз.

Схема автоматически добавляет active со значением true в старые базы при выполнении schema.sql. Это не меняет существующие заказы и цены их позиций.
